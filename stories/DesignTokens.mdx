# Design Tokens

**Design tokens** are the foundation of Aural UI's themeable architecture. They're CSS custom properties (variables) that control every visual aspect of the design system.

> 🎨 **Designing in Figma?** These same tokens ship as **Figma Variables** in the [Aural UI Figma kit](https://www.figma.com/community/file/1649056373718832084/aural-ai) — primitives feed semantic tokens, switchable across all 9 theme modes, so design and code stay in sync.

---

## 🎯 How Tokens Work

Aural UI uses a **two-layer token system**:

### Layer 1: Primitive Tokens (Foundation)

These are the actual color values that **never change** across themes:

```css
:root {
  /* Color scales: 50 (lightest) → 950 (darkest) */
  --primary-400: #5ebd8f; /* Vibrant green */
  --secondary-500: #06b6d4; /* Cyan */
  --neutral-100: #f5f5f5; /* Light gray */
  --neutral-900: #171717; /* Dark gray */
}
```

### Layer 2: Semantic Tokens (Meaning)

These tokens map to **purposes** and **change per theme**:

```css
/* Dark Theme */
:root {
  --color-bg-primary: #0f0f1a; /* Dark background */
  --color-text-primary: #f5f5fa; /* Light text */
}

/* Light Theme */
:root {
  --color-bg-primary: #ffffff; /* Light background */
  --color-text-primary: #111827; /* Dark text */
}
```

**Same token name, different values per theme!**

### Layer 3: Components Use Semantic Tokens

```css
.btn-primary {
  background: var(--color-button-primary-bg);
  color: var(--color-button-primary-text);
}

.card {
  background: var(--color-card-bg);
  border: 1px solid var(--color-border-subtle);
}
```

### Size

<div style={{

`--size-N` sizes a UI element's **own box** — icon dimensions, avatar diameter, status-dot size, toggle track/thumb — as opposed to `--space-N`, which sizes the **gap between** elements.

> ⚠️ **Not the same convention as `--space-N`.** `--size-N`'s `N` is the **literal pixel value** — `--size-14` is 14px, `--size-44` is 44px. `--space-N` uses `N` = px ÷ 4, so `--space-14` is **56px**. Never assume `--size-N` and `--space-N` with the same `N` are interchangeable — always check the actual value.

Where a size value coincides with an existing `--space-N` value, `--size-N` aliases it instead of duplicating the literal (e.g. `--size-16: var(--space-4)`), so the two scales stay numerically consistent even though their naming conventions differ.

```css
--size-6: 0.375rem; /* 6px  — status dot */
--size-14: 0.875rem; /* 14px — small icon */
--size-18: 1.125rem; /* 18px — medium icon */
--size-24: var(--space-6); /* 24px — large icon */
--size-36: 2.25rem; /* 36px — small toggle track */
--size-40: var(--space-10); /* 40px — avatar */
--size-44: 2.75rem; /* 44px — touch target */
```

**Do / don't:**

```css
/* Don't — raw px for a control dimension */
.status-dot {
  width: 6px;
  height: 6px;
}

/* Don't — reaching for the wrong scale by number-matching intuition */
.icon-md {
  width: var(--space-14);
} /* this is 56px, not 14px! */

/* Do */
.status-dot {
  width: var(--size-6);
  height: var(--size-6);
}
.icon-md {
  width: var(--size-18);
}
```

### Z-Index

Two layers, same pattern as color: a **core scale** of raw, meaningless rungs (`--z-0` through `--z-90`), and a **semantic scale** of intent-named aliases onto those rungs (`--z-dropdown`, `--z-modal`, `--z-popover`, and so on). The jumps between rungs are deliberately uneven — they were set to match stacking values already in use across components (dropdowns at 1000, overlays near 9999, etc.), so introducing the token scale didn't change any existing stacking behavior.

**Core scale:**

```css
--z-0: 0;
--z-40: 100;
--z-70: 9998;
--z-10: 10;
--z-50: 1000;
--z-80: 9999;
--z-20: 20;
--z-60: 2000;
--z-90: 10000;
--z-30: 30;
```

**Semantic scale:**

| Token          | Resolves to           | Use for                                                                                           |
| -------------- | --------------------- | ------------------------------------------------------------------------------------------------- |
| `--z-sticky`   | `var(--z-40)` · 100   | Sticky in-flow elements, e.g. a sticky navbar                                                     |
| `--z-dropdown` | `var(--z-50)` · 1000  | Floating panels anchored to a trigger: dropdown, select, combobox, date/time pickers, suggestions |
| `--z-modal`    | `var(--z-60)` · 2000  | App-level modal backdrop + content                                                                |
| `--z-overlay`  | `var(--z-70)` · 9998  | A secondary overlay above a modal, e.g. a drawer backdrop                                         |
| `--z-popover`  | `var(--z-80)` · 9999  | Content that must float above everything in normal flow                                           |
| `--z-tooltip`  | `var(--z-80)` · 9999  | Same layer as popover — tooltips                                                                  |
| `--z-toast`    | `var(--z-80)` · 9999  | Same layer as popover — toast notifications                                                       |
| `--z-max`      | `var(--z-90)` · 10000 | Absolute top layer: command palette, snackbar, lightbox, submenus                                 |

**When to use it — and when not to:**

Component code should reference the **semantic tokens** (`var(--z-dropdown)`), not the raw `--z-N` rungs, so the meaning of a layer is visible at the call site.

Small z-index values used purely for local stacking tricks inside a single component are **not** part of this scale and don't need a token. If you're layering a decorative pseudo-element above its own container, ordering a badge dot over an avatar, or doing any z-index trick where everything being stacked lives inside one component's own DOM subtree — and the value is 20 or smaller — leave it as a plain integer. Reach for a global token only when the element needs to stack above or below content belonging to a **different** component.

```css
/* Local stacking trick — stays a plain small integer, no token needed */
.avatar-status-dot {
  position: absolute;
  z-index: 1;
}

/* Cross-component global layer — use the semantic token */
.dropdown-menu {
  position: absolute;
  z-index: var(--z-dropdown);
}
.modal-backdrop {
  position: fixed;
  z-index: var(--z-modal);
}
```

**Do / don't:**

```css
/* Don't — raw global-scale number, meaning not visible at the call site */
.toast {
  z-index: 9999;
}

/* Don't — reaching past the semantic layer for no reason */
.toast {
  z-index: var(--z-80);
}

/* Do */
.toast {
  z-index: var(--z-toast);
}
```

### Transitions & Animation

Aural UI ships a full motion token system with three layers: **durations**, **easing functions**, and **composite transitions**. Every animated component uses these tokens, so motion is always consistent and easy to override per theme.

> 📖 **See the live interactive demos** in [Design System → Animation & Transitions](?path=/docs/design-system-animation-transitions--docs) — including an easing playground, duration comparison, and per-token reference table.

#### Duration scale

All six steps are available as both CSS custom properties and Figma Variables (`Aural/Animation / duration/*`, type **FLOAT** in ms):

```css
--duration-instant: 0ms; /* No visible motion — toggles, focus rings */
--duration-fast: 150ms; /* Micro-interactions: hover, button press */
--duration-normal: 300ms; /* Menus, tooltips, modals */
--duration-slow: 500ms; /* Drawers, page transitions */
--duration-slower: 750ms; /* Emphasis, onboarding */

```

```css
--transition-fast: 150ms ease-in-out;
--transition-normal: 300ms ease-in-out;
--transition-slow: 500ms ease-in-out;
--transition-all-fast: all 150ms ease-in-out;
--transition-all-normal: all 300ms ease-in-out;
--transition-colors: color 150ms, background-color 150ms, border-color 150ms;
--transition-transform: transform 150ms ease-in-out; /* GPU composited */
--transition-opacity: opacity 300ms ease-in-out; /* GPU composited */
```

</div>

**Usage:**

```css
/* Use a composite token for the common case */
.btn {
  transition: var(--transition-all-fast);
}

/* Or compose duration + easing yourself */
.drawer {
  transition: transform var(--duration-slow) var(--ease-spring);
}

/* Prefer GPU-composited properties for performance */
.modal-overlay {
  transition: var(--transition-opacity);
}
```

**When to use which easing:**

| Easing      | Token           | Best for                           |
| ----------- | --------------- | ---------------------------------- |
| ease-out    | `--ease-out`    | Things appearing on screen         |
| ease-in     | `--ease-in`     | Things disappearing off screen     |
| ease-in-out | `--ease-in-out` | Default — moving within the screen |
| linear      | `--ease-linear` | Spinners and progress bars         |
| bounce      | `--ease-bounce` | Playful confirmations              |
| spring      | `--ease-spring` | Modals, drawers, natural snapping  |

**Figma Variables:** All duration values are `FLOAT` variables and all easing strings are `STRING` variables in the `Aural/Animation` collection. Figma does not yet support binding animation variables to layer properties directly, but they serve as accurate spec references for handoff.

## 🎨 Creating Custom Themes

### Method 1: Override Individual Tokens

```html
<style>
  :root {
    /* Change primary brand color */
    --color-primary: #8b5cf6; /* Purple */

    /* Adjust spacing scale */
    --space-4: 1.25rem; /* Increase base spacing */

    /* Rounder corners */
    --radius-md: 1rem; /* More rounded */
  }
</style>
```

### Method 2: Create a Full Custom Theme

```css
/* my-brand.css */
:root {
  /* Brand Colors */
  --color-primary: #8b5cf6;
  --color-secondary: #ec4899;

  /* Backgrounds (Dark Theme) */
  --color-bg-primary: #1a1a1a;
  --color-bg-secondary: #2a2a2a;
  --color-bg-tertiary: #3a3a3a;

  /* Text */
  --color-text-primary: #ffffff;
  --color-text-secondary: #a0a0a0;

  /* Borders */
  --color-border-subtle: rgba(255, 255, 255, 0.1);

  /* Typography */
  --font-sans: 'Inter', system-ui, sans-serif;

  /* Spacing - Compact Scale */
  --space-4: 0.875rem;
  --space-6: 1.25rem;
}
```

**Load it:**

```html
<link rel="stylesheet" href="aural-ui.css" /> <link rel="stylesheet" href="my-brand.css" />
```

## 🔧 Advanced Techniques

### Token Composition

Combine tokens to create new values:

```css
:root {
  --duration-fast: 150ms;
  --ease-in-out: cubic-bezier(0.4, 0, 0.2, 1);

  /* Compose them */
  --transition-fast: var(--duration-fast) var(--ease-in-out);
}
```

### Math with Tokens

Use `calc()` for dynamic values:

```css
.double-padding {
  padding: calc(var(--space-4) * 2); /* 2rem */
}

.half-margin {
  margin: calc(var(--space-4) / 2); /* 0.5rem */
}
```

### Fallback Values

Provide defaults for missing tokens:

```css
.card {
  /* If --radius-md doesn't exist, use 0.75rem */
  border-radius: var(--radius-md, 0.75rem);
}
```

## 💡 Best Practices

1. **Use semantic tokens in components** - Reference `--color-bg-primary`, not `--neutral-900`
2. **Don't hardcode values** - Always use tokens for consistency
3. **Test in multiple themes** - Switch themes to ensure proper contrast
4. **Override sparingly** - Only customize what you need
5. **Document custom tokens** - Comment your customizations
