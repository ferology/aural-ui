Color Contrast Analysis Report

WCAG 2.1 AA results for all Aural UI themes, updated 2026-10-10

Key Findings

  • All 11 themes pass the audit. npm run audit:contrast resolves the semantic color tokens in a real browser and checks the pairs components use: text on the three surfaces at 4.5:1, form control borders at 3:1 (WCAG 1.4.11). Every pair passes in every theme.
  • This report replaces the 2026 pre-remediation findings. The earlier version reported a 40% pass rate for the light theme and a 2.11:1 primary button in the dark theme. Those figures are kept below as "Before" for reference only.
  • Lowest text ratio across themes: 4.51:1 (warm, nav active text; neon, error-text on bg-elevated). Every text pair is at or above 4.5:1.
  • Lowest control border ratio across themes: 3.03:1 (high-contrast, on bg-elevated). Every control border pair is at or above 3:1.

How the fixes are structured

  1. Filled status backgrounds: use --color-{success,error,info,warning}-solid with --color-text-on-* text.
  2. Status text and icons on surfaces: use --color-{success,error,warning,info}-text. It resolves to the 400 shades on dark themes and the 700/600 shades in the light and minimal themes.
  3. Form control boundaries: use --color-control-border (input, checkbox, radio, select). Subtle and medium borders are decorative only.
  4. Primary button text: --color-button-primary-text defaults to var(--color-bg-primary) (dark on the dark theme, white on the light theme).
  5. Check before shipping: run npm run build:css && npm run audit:contrast. It exits 1 if any pair fails.

Running the audit

npm run build:css
npm run audit:contrast              # all 11 themes
node scripts/contrast-audit.mjs dark light   # selected themes

The script launches a browser (Playwright Chromium), loads dist/aural-ui.css plus each theme, and exits 1 if any pair is below its required ratio.
